Detailed Description

Header-only DNS resolver that queries over a generic Arduino Client rather than UDP.

TinyDNSClient speaks DNS-over-TCP framing (RFC 1035 section 4.2.2) on top of whatever Client implementation is supplied, so it works with WiFiClient/EthernetClient (plain DNS-over-TCP, port 53) as well as WiFiClientSecure (DNS-over-TLS, port 853). Each call to resolve() / resolveV6() connects, sends one query, reads the response, and disconnects again, so the Client can be reused for other purposes between calls.

bool resolve ( String &  io)
inline

Resolve the hostname embedded in a URL (or a bare hostname) in place, replacing it with its resolved IPv4 address.

Recognizes an optional "scheme://" prefix and an optional ":port" or "/path" suffix; only the hostname portion between them is replaced, everything else is left untouched. For example "http://example.com:8080/foo" becomes "http://93.184.216.34:8080/foo".

Parameters
ioString holding a hostname or URL; rewritten in place on success, left unmodified on failure.
Returns
true if the hostname resolved successfully and io was updated, false otherwise (see lastResult() for the reason).

Enable or disable captive mode.

While captive mode is active, resolve() answers every hostname with localAddress without contacting the DNS server, so clients are redirected to the local device (e.g. a captive portal). resolveV6() reports NotFound in this mode.

Parameters
enabledtrue to enable captive mode, false to disable it.
