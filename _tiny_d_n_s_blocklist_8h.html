Detailed Description

Suffix-matching domain blocklist and allowlist for TinyDNSServer.

A rule for "ads.example.com" also covers every subdomain ("a.b.ads.example.com"). Lookups walk the query name from the full name toward the TLD, and the first (most specific) rule that matches decides:

  • an allowlist rule returns TinyDNSBlockAction::Allow
  • a blocklist rule returns TinyDNSBlockAction::Block
  • if the same name is in both lists, the allowlist wins

So with "block ads.com" and "allow good.ads.com", good.ads.com and its subdomains are allowed, while ads.com and other subdomains are blocked.

Rules are stored in an open-addressing hash table with FNV-1a hashes. Each domain costs roughly its length plus 1 byte in a string pool and 12 bytes of table slot at a 75% maximum load factor. On boards with PSRAM (ESP32 with BOARD_HAS_PSRAM, RP2350 with RP2350_PSRAM_CS) both the table and the pool are allocated there; see TinyDNSMemory.h. Define TINY_DNS_NO_PSRAM to keep them in internal RAM. Create the blocklist after PSRAM is initialized, for example as a member of the server built in setup().

Lists are read in hosts-file format, the same as StevenBlack and similar lists:

0.0.0.0 ads.example.com
127.0.0.1 tracker.example.net # trailing comments are allowed
0.0.0.0 *.ads.example.org # leading "*." is stripped

AdBlock lists are accepted too: "||ads.example.com^" blocks a domain and "@@||ads.example.com^" allows it. Rules with options ("$...") or cosmetic filters ("##") are skipped.

Plain lists with one domain per line (no address) are accepted too. Lines whose address is not a sinkhole address (0.0.0.0, 127.0.0.1, ::, ::1) are skipped, so a line like "192.168.1.10 nas" is not blocked. Localhost-style names from hosts files (localhost, broadcasthost, ip6-*, ...) are skipped.

Usage:

TinyDNSServer server(upstream);
File f = SD.open("/blocklist/hosts.txt");
server.blocklist().loadHosts(f);
f.close();
server.blocklist().allowDomain("api.example.com");
