Detailed Description

Read-only, Huffman-coded set of blocked domains, stored in PROGMEM.

The data is produced by tools/gen_huffman_blocklist.py. Format (version 1):

  • Domains are reversed label by label ("ads.example.com" becomes "com.example.ads"), sorted, and front-coded. Each record is a shared prefix length (0..255) and the remaining bytes, followed by a 0 byte.
  • Every blockSize-th record is a restart point with shared length 0, so each block can be decoded without reading the records before it.
  • Two bit streams, MSB first: the shared lengths ("prefix stream") and the record bytes ("suffix stream"). Each stream has its own canonical Huffman code, given as 256 code lengths (0 = unused symbol, max 15).
  • The block index holds, per block, the bit offset of the block's first record in each stream as two big-endian uint32 values (8 bytes/block).

Lookup: a binary search over the blocks decodes each block's first domain, then the matching block is decoded record by record. Memory in RAM is the two decode tables (about 0.6 KB) plus a few small buffers on the stack.

Generate the store with tools/gen_huffman_blocklist.py. With –format incbin the tables are binary files next to the header, embedded with .incbin (GCC-based cores only). With –format carray they are C arrays.

Usage:

#include "blocklist_data.h" // generated; defines adblock_store (PROGMEM)
TinyDNSHuffmanStore store(adblock_store);
store.begin();
bool blocked = store.contains("tracker.example.com");
